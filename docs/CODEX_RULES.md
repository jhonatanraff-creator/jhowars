# Regras do Codex para Jhow.ars

1. Nunca trabalhar diretamente na `main`.
2. Nunca fazer merge automaticamente.
3. Não redesenhar nenhuma área sem instrução explícita.
4. Não inventar conteúdo.
5. Não alterar textos durante tarefas de implementação sem solicitação.
6. Não simplificar uma composição visual aprovada.
7. Não transformar layouts específicos em cards genéricos por conveniência.
8. Quando existir Figma aprovado, ele é a fonte visual de verdade.
9. HTML legado não define a nova interface.
10. Alterar somente o escopo solicitado em cada rodada.
11. Preservar componentes já aprovados.
12. Validar desktop e mobile antes de declarar uma implementação concluída.
13. Nunca declarar QA aprovado apenas porque o código compilou.
14. Dizer claramente quando não conseguir validar algo.
15. Não criar dados falsos para preencher lacunas.
16. Não substituir um asset por aproximação quando o original existir.
17. Antes de grandes alterações, documentar impacto esperado.
18. Evitar refactors fora do escopo.
19. Não publicar possíveis notas internas marcadas no inventário sem revisão humana.
20. CMS seeds devem ser não destrutivos; nunca sobrescrever documentos existentes ou gravar em produção sem confirmação explícita.
